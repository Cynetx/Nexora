# Parham VPN

اپ کاربر + اپ ادمین؛ هر دو مستقیم با **Supabase** کار می‌کنند. دیگر سرور جدا و آدرس `127.0.0.1` لازم نیست
(پوشه‌ی `server/` قدیمی است و استفاده نمی‌شود).

## راه‌اندازی (فقط یک بار)
1. در Supabase: **SQL Editor › New query**، محتوای `supabase.sql` (کنار همین فایل؛ همان `tools/supabase.sql`) را بچسبان و Run بزن
   (یا در اپ ادمین تب «دیتابیس» › «کپی SQL»).
2. با `builder.html` اپ‌ها را بساز: آدرس پروژه + کلید **anon/publishable** را بده.
3. اپ ادمین را باز کن › تب «دیتابیس» › کلید **service_role / secret** را بگذار › «ذخیره و تست اتصال».
   بعد از وصل شدن، آمار، کاربران و کانفیگ‌ها خودکار روشن می‌شوند.
4. تب «کانفیگ‌ها» › «کانفیگ / ساب»: لینک ساب یا چند کانفیگ را بچسبان؛ کانفیگ‌ها خودکار استخراج می‌شوند.

## امنیت
- کلید anon داخل اپ کاربر است و فقط می‌تواند کانفیگ‌های فعال را بخواند و رویداد اتصال بفرستد.
- کلید service_role فقط داخل اپ ادمین روی گوشی خودت ذخیره می‌شود؛ هرگز داخل اپ کاربر نگذار.

## خروجی‌های اندروید
- `*-universal.apk` روی همه‌ی گوشی‌ها
- `*-arm64-v8a.apk` گوشی‌های 64 بیتی (سبک‌تر)
- `*-armeabi-v7a.apk` گوشی‌های 32 بیتی (قدیمی)
- `ParhamVPN-GooglePlay.aab` برای آپلود در Google Play (امضاشده)

## امضای Google Play
- بار اول، workflow خودش یک keystore می‌سازد و داخل ریپوی خصوصی (`keystore/`) نگه می‌دارد.
- `keystore-backup` را حتما جای امن ذخیره کن. در Play Console «Play App Signing» را فعال کن.
- کلید خودت را داری؟ secrets: `ANDROID_KEYSTORE_BASE64`، `ANDROID_KEYSTORE_PASSWORD`، `ANDROID_KEY_ALIAS`.


## نسخه‌ی NEXORA
- برنامه‌ی کاربر: NEXORA VPN (آیکون از tools/nexora_icon.png)؛ اندروید: universal / arm64-v8a / armeabi-v7a، ویندوز، لینوکس و مک با رابط مخصوص
- برنامه‌ی ادمین: NEXORA Admin (فقط universal)
- نام کانفیگ: اگر هنگام افزودن نام ندهی، با پرچم و نام کشور سرور ثبت می‌شود

## بکاپ و کلید anon (اپ ادمین › تب دیتابیس)
- **بکاپ و بازگردانی**: دانلود فایل کامل (کانفیگ‌ها، کاربران، رویدادها)، کپی بکاپ، بازگردانی از کلیپ‌بورد، و «نسخه‌ی امن در دیتابیس» (۱۰ نسخه‌ی آخر داخل خود Supabase). کلیدها داخل بکاپ نمی‌روند.
- **کلید anon**: حتما در builder وارد کن؛ گزینه‌ی «اتصال دیتابیس» از اپ کاربر حذف شد.
- SQL تقویت‌شده (ایندکس، قید، تابع پاک‌سازی رویدادهای قدیمی) در `tools/supabase.sql`؛ دوباره اجرا کردنش امن است.

## نسخه‌ی اصلاحات اخیر
- **SQL جدید (حتما یک بار دوباره اجرا کن):** در اپ ادمین › تب دیتابیس › «کپی SQL» › Supabase › SQL Editor › Run. اگر ستون id جدول‌ها عددی (bigint) مانده بود، به متن تبدیل می‌شود (خطای `22P02` و صفر ماندن آمار از همین بود). داده‌ها پاک نمی‌شوند.
- بعد از اجرا: تب دیتابیس › «تست ثبت کاربر و کانفیگ» نتیجه را نشان می‌دهد.
- شش کانفیگ پیش‌فرض یک بار داخل دیتابیس گذاشته می‌شوند و در تب کانفیگ‌ها دیده می‌شوند؛ نام/لوکیشن خودکار.
- آمار هر ۱۰ ثانیه و کاربران فعال/غیرفعال/کل هر ۳ ثانیه به‌روز می‌شود. بکاپ خودکار روزانه داخل دیتابیس.
- آیپی سرور هیچ‌جا نمایش داده نمی‌شود؛ فقط لوکیشن.

- **SQL نسخه‌ی 3:** ستون‌های اضافه‌ی NOT NULL جدول‌های قدیمی را آزاد می‌کند (خطای 23502)، نوع ستون‌ها و کلید اصلی را درست می‌کند و در انتها گزارش سلامت (`select * from public.nexora_health();`) نشان می‌دهد. دکمه‌ی «کپی SQL» همین نسخه را می‌دهد.


## موتور اتصال جدید (تونل شخصی + تست پینگ + DNS رمزنگاری‌شده)
- **ترتیب مراحل:** ساخت تونل شخصی (کلید X25519) ← تست پینگ DNS (Cloudflare، Google، Quad9، AdGuard با DoH) ← تست پینگ واقعی کانفیگ‌ها ← اتصال.
- **پینگ قبل از اتصال:** هر کانفیگ دو بار پینگ TCP می‌شود. Timeout یا عدد نامعتبر (کمتر از ۱ یا بیشتر از ۳۰۰۰ms) یعنی به آن کانفیگ وصل نمی‌شود و خودکار نوبت کانفیگ بعدی لیست است.
- **خروج از برنامه:** اگر وسط مراحل (قبل از کامل شدن) از برنامه بیرون بروی، اتصال لغو می‌شود و برقرار نمی‌شود.
- **DNS:** سریع‌ترین DNSهای سالم به‌صورت DoH (`https+local://`) داخل هسته‌ی Xray گذاشته می‌شوند.
- **تونل DNS با Noise (اختیاری):** `Noise_NK_25519_ChaChaPoly_SHA256`؛ پیام‌ها داخل نام کوئری DNS (base32) و از راه چند resolver می‌روند و resolver فقط بایت رمزشده می‌بیند.
  برای فعال شدن به سرور تونل نیاز است: در ریپو › Settings › Variables این دو متغیر را بساز: `TUNNEL_DOMAIN` و `TUNNEL_PUBKEY` (۶۴ کاراکتر hex).
  بدون آن‌ها فقط تست DNS و DoH اجرا می‌شود.
- **لینوکس و مک:** اتصال با پروکسی سیستم انجام می‌شود (نه تونل کامل): لینوکس با GNOME/KDE، مک با `networksetup`. مک بدون امضای اپل ساخته می‌شود؛ بار اول با راست‌کلیک › Open یا `xattr -cr` اجرا کن و اگر تنظیم پروکسی رمز ادمین خواست، تأیید کن.
- **خطای ۱۴۳ در بیلد اندروید:** Gradle با `-Xmx8G` روی runner کشته می‌شد؛ حالا `patch_android.py` مقدار را ۳GB می‌کند، swap اضافه شده و daemonها بین بیلدها بسته می‌شوند.

## دیتابیس: جدول‌ها و امنیت (tools/supabase.sql)
- جدول‌ها: `users`، `configs`، `events`، `connections` (هر نشست اتصال)، `messages` (پیام‌های ادمین برای کاربران)، `backups`.
- RLS روی همه‌ی جدول‌ها روشن است. کاربر عادی (کلید anon) فقط **خواندن** دارد: کانفیگ‌های فعال و پیام‌های فعال.
- Insert / Update / Delete برای کاربر عادی با policy از نوع RESTRICTIVE بسته است؛ فقط کلید service_role (اپ ادمین) می‌نویسد، و اپ کاربر فقط از راه تابع امن `report_event`.
- جدول‌های users / events / connections / backups برای کاربر عادی حتی خواندنشان هم بسته است.
- اجرای دوباره‌ی فایل SQL امن است (اگر جدول قدیمی داشتی، ستون‌های جدید خودکار اضافه می‌شوند).

## ساخت روی GitHub رایگان
- ریپو خصوصی است (keystore داخلش می‌ماند)؛ پلن رایگان ماهانه ۲۰۰۰ دقیقه می‌دهد: Linux ×۱، Windows ×۲، macOS ×۱۰.
- اندروید ≈ ۳ ساخت (universal + arm64/armv7 با یک ساخت + ادمین)؛ AAB فقط با گزینه‌ی `aab`.
- مک به‌طور پیش‌فرض خاموش است (۱۰ برابر دقیقه)؛ ادمین ویندوز فقط با گزینه‌ی `admin_desktop`.
- فایل‌های خروجی ۲ روز نگه داشته می‌شوند تا فضای ۵۰۰ مگابایتی Artifact پر نشود؛ ساخت‌های قدیمی خودکار لغو می‌شوند.

## پینگ واقعی (Relay) و صفحه‌ی کره‌ی زمین

- پینگ سرورها و مرحله‌ی «تست پینگ» موقع اتصال دیگر TCP ساده نیست: هر کانفیگ داخل هسته‌ی خودش
  (اندروید: v2ray، ویندوز/لینوکس/مک: xray) بالا می‌آید و یک درخواست HTTP کامل (`generate_204`) از داخل آن زده می‌شود.
- هنگام اتصال یک صفحه‌ی تمام‌صفحه با کره‌ی دیجیتال باز می‌شود (`client/lib/connect_globe.dart`):
  موفق → چرخش به کشور، روشن شدن مرز، نام انگلیسی کشور و شکل کشور؛ ناموفق → کره از وسط ترک می‌خورد و می‌افتد.
- داده‌ی مرز کشورها (world-atlas 110m) را workflow موقع ساخت داخل `client/assets/geo/` دانلود می‌کند؛
  اگر نبود، اپ یک‌بار دانلود و ذخیره می‌کند. بدون این داده کره بدون خشکی/مرز نمایش داده می‌شود.
